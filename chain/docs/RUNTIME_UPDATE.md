# Runtime Update Playbook

**There is no runtime upgrade on a Qnero chain.** A runtime change is a new node
release and a new genesis.

This file used to be a referendum runbook: submit a `fast_upgrade` proposal,
collect the collective's ayes, wait out the enactment period, then deliver the
wasm with `system.apply_authorized_upgrade`. Every piece of that is gone. The
tech collective, its referenda instance and the `FastUpgrade` origin were
removed from the runtime, and the nine `frame-system` dispatchables that could
write `:code`, `:heappages` or a raw storage key were deleted from the fork. No
origin can replace the code, because the function that writes the code key does
not exist. `docs/DESIGN.md` section 7.6 carries the decision and its cost;
`runtime/tests/no_admin_keys.rs` carries the proof.

What follows is what replaces it.

---

## What a release is

A consensus change is:

1. a new runtime compiled into a new node binary,
2. a new chain spec generated by `scripts/build-testnet-spec.sh`,
3. a new genesis hash, a new network identity, a fresh database,
4. and a coordinated restart.

A node that runs the new binary against the old spec runs the old rules,
because the runtime a chain executes is the one written into its own state at
genesis and nothing can rewrite it. The two chains cannot be confused by an
extrinsic replay either: `CheckGenesis` refuses a transaction signed for one on
the other.

The practical shape of a release is therefore: publish the binary, publish the
spec with its hash, announce the switch, and let the old chain stop.

## What does not carry over

Balances do not carry over unless a preset re-mints them, and **pool notes
cannot be re-minted at all**. A shielded balance is a commitment set: no new
genesis can reproduce it. Only transparent allocations can be carried across,
and only by writing them into a preset by hand.

That is the whole cost of the decision, and it is why every measurement and
every item of a pre-genesis bundle has to be finished before the genesis is
cut. After it there is no second bundle.

## Version numbers

`spec_version` still moves whenever the metadata moves, and it still means what
it meant: every client that caches metadata keys that cache on it. The rule
lives above `VERSION` in `runtime/src/lib.rs`, and
`runtime/tests/call_filter.rs::the_runtime_identity_is_pinned` is the tripwire.

What changed is that it can only ever move with a new genesis. There is no
sequence of two versions on one chain any more, so `Migrations` is `()` and
stays `()`: a migration exists to carry state from one runtime to its successor
on the same chain, and this chain has no such successor.

`transaction_version` moves only when the signed extrinsic encoding does: the
`TxExtension` set or the payload layout. A change to how signatures are
produced or verified does not require it.

## Procedure

1. Land the runtime change and bump `spec_version` in `runtime/src/lib.rs`, with a paragraph in the changelog block above `VERSION` naming what moved in the metadata.
2. Run the release gates: `docs/RELEASE_PREFLIGHT.md`.
3. Regenerate the chain spec: `scripts/build-testnet-spec.sh`. `node/tests/testnet_spec.rs` compares the committed file against what the binary exports byte for byte, so a preset edit nobody re-exported fails there rather than shipping.
4. Record the new genesis hash. Publish the binary and the spec together, with that hash beside them; whoever holds the file picks the genesis they join, which is why it is published with its hash.
5. Announce the switch and the time. Operators stop the old node, take a fresh base path, and start the new binary against the new spec.
6. Rebuild every client against the new genesis: the CLI wallet, Qloak, the explorer and the faucet each bind a wallet store or a scan checkpoint to the genesis hash.

## What still looks like authority and is not

Three things, and each is an operator's own choice rather than a power over
anybody else.

- **A chain spec is the chain.** Whoever hands you the file picks the genesis you join. That is true of every chain, and it is why the file is published with its hash.
- **`codeSubstitutes`**, honoured by the client, lets a node execute different code for a given block. The shipped spec's map is empty and `node/tests/testnet_spec.rs::the_shipped_spec_carries_no_code_substitute` keeps it that way, so the field is a decision rather than a default.
- **`--wasm-runtime-overrides`** does the same from a directory.

Both of the last two change one node's execution. A node that executes
different rules from its peers leaves the chain rather than steering it.

## Signing

Polkadot-JS Apps and the standard `@polkadot/api` cannot sign for this chain
(ML-DSA-87 signatures). Use the Qnero CLI wallet.
